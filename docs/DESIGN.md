## 1. 플로팅·화면 모드

### 현재 동작

- 채팅창은 치지직 `#aside-chatting`, 유튜브 `ytd-live-chat-frame`을 우선 찾고, 치지직 CSS module 클래스의 해시 앞 접두어(`chatting_area` 등) 부분 일치를 보조 후보로 쓴다. id에 `chat`이 들어간 요소 같은 범용 후보는 쓰지 않으며, 자동 인식이 틀리거나 실패하면 Alt+Shift+P로 사용자가 영역을 직접 지정한다.
- 채팅 내용이 있는지 판단할 때 확장이 넣은 UI(글자 크기 도구, `chat-dungsil-*` 요소)의 문구는 세지 않는다. 도구만 남은 빈 컨테이너는 채팅으로 보지 않는다.
- 화면 모드는 일반·T(극장)·전체화면 세 가지이며, 위치·크기를 모드별로 따로 저장한다.
- 일반·T 모드에서는 채팅 요소를 제자리에서 CSS로 띄우고 DOM을 옮기지 않는다. 실제 전체화면(Fullscreen API)에서만 채팅 요소를 전체화면 요소 안으로 옮기고, 나올 때 원래 자리로 되돌린다.
- 전체화면에 들어가면 채팅을 자동으로 플로팅하고, 채팅 UI가 늦게 나타나면 전체화면에 있는 동안 계속 감지한다. T 모드 자동 분리는 사이트별 설정(기본 꺼짐)이다. 단축키로 직접 켠 플로팅은 화면 모드가 바뀌어도 유지한다.
- 사이트 리렌더링으로 채팅 요소가 교체되면 새 요소로 갈아타고, 사이트가 채팅을 숨기면 원래 자리로 복구한 뒤 다시 나타날 때를 기다린다.
- 창을 줄여 채팅이 화면 밖으로 나가면 화면 안으로 임시 보정하고, 창을 다시 키우면 저장된 위치·크기를 적용한다. 임시 보정 값은 저장하지 않는다.
- 유튜브는 채팅 패널(`ytd-live-chat-frame`) 자체를 플로팅해 내부 iframe이 바뀐 크기를 따르게 한다.

### 결정과 이유

- 전체화면에서는 전체화면 요소 밖의 DOM이 렌더링되지 않으므로 이때만 DOM을 옮긴다. 그 외 모드에서 DOM을 옮기면 사이트 React 트리와 충돌할 위험이 커서 CSS 배치만 쓴다.
- 클래스 이름의 해시 부분은 배포마다 바뀌므로 역할을 나타내는 접두어로만 찾는다.
- 범용 `[id*="chat"]` 후보는 유튜브 팝아웃 창의 채팅 영역이나 확장 자체 UI까지 채팅창으로 오인해 제거했다. 알 수 없는 구조는 자동으로 잡지 않고 수동 지정에 맡긴다.
- T 모드 위치를 한 번도 저장하지 않았다면 일반 모드 위치를 이어받아 첫 진입 때 엉뚱한 위치에 나타나지 않게 한다.
- J 키는 치지직 기본 동작(채팅 활성화)을 가로채지 않고, 사이트가 채팅을 다시 띄우면 자동 감지가 이어받는다. 유튜브의 J(되감기)는 건드리지 않는다.

### 알려진 한계

- 유튜브에서 전체화면 진입·이탈 시 DOM 재배치로 채팅 iframe이 한 번 새로고침될 수 있다(1~2초).
- 유튜브 채팅 iframe 안에 포커스가 있으면 페이지 단축키가 전달되지 않는다.
- 사이트 구조가 크게 바뀌면 자동 인식이 실패할 수 있으며, 이 경우 수동 지정에 의존한다.

## 2. 외부 PiP

### 현재 동작

- 확장 팝업의 스위치나 페이지의 「외부 PiP 창 열기」 버튼으로 Document Picture-in-Picture 창을 연다. 창에는 사이트의 독립 채팅 페이지를 iframe(`name=chat-dungsil-pip`)으로 표시하고, 상단에 글자 크기 툴바를 붙인다.
  - 치지직: `/live/<channelId>/chat`
  - 유튜브: 페이지 채팅 iframe의 `live_chat`/`live_chat_replay` 주소, 없으면 `/live_chat?v=<videoId>&is_popout=1`
- PiP가 열려 있는 동안 원래 채팅은 가리고, 페이지 안 이동·잠금·숨김 제어와 수동 지정은 비활성화한다.
- 팝업 스위치 OFF와 PiP 창 ✕는 같은 결과를 낸다. 열기 직전의 도킹·플로팅·숨김 상태로 복원한다.
- 원본 방송 주소 변경·새로고침·탭 종료 시 PiP를 닫는다.
- 팝업 스위치는 현재 창의 실제 열림 상태를 표시할 뿐, 다음에 자동으로 다시 여는 저장 설정이 아니다.
- Document PiP 창은 브라우저 전체에서 하나만 열린다. 채팅 PiP와 모아보기 PiP는 서로를 닫으며, 닫힌 쪽은 원래 상태로 복원한다.

### 결정과 이유

- 사이트의 React 채팅 하위 트리를 PiP 문서로 옮기지 않고 독립 채팅 페이지를 새로 연다. 이벤트·스타일이 원본 문서에 묶여 있어 옮기면 동작을 보장할 수 없기 때문이다.
- 확장 팝업 클릭 → 확장 메시지 → `requestWindow` 경로로 연다. 사용자 클릭 활성화를 유지하도록 `requestWindow` 호출 전에 `await`를 두지 않는다. 브라우저가 이 경로를 거부(`NotAllowedError`)하면 페이지에 직접 클릭할 열기 버튼을 표시한다.
- 창의 기본 크기만 제안하고 화면 좌표는 지정하지 않는다. 창 위치는 OS·브라우저에 맡긴다.
- 페이지 안 드래그나 자동 화면 모드 변경이 PiP로 옮긴 채팅을 원래 페이지로 끌어오지 않도록 PiP 동안 플로팅 제어를 멈춘다.

### 알려진 한계

- 입력 중이던 문장과 스크롤 위치는 PiP로 옮겨지지 않는다.
- 원본 방송 탭이 열려 있어야 한다.
- OS의 항상 위 표시, 다른 앱 전체화면과의 겹침은 headless 환경에서 검증할 수 없어 환경에 따라 다를 수 있다.

## 3. 글자 크기

### 현재 동작

- 일반 채팅의 닉네임·본문을 12~24px로 고정한다. 값이 없으면(기본값) 사이트 원래 크기를 쓴다. 사이트별로 저장한다.
- 확장 팝업의 슬라이더·기본값 버튼과, 채팅 상단의 −/현재 크기/+/기본 툴바로 조절한다. 툴바는 방송 페이지(도킹·플로팅)·외부 PiP·채팅 팝업 창에 같은 모양으로 붙는다. 어느 곳에서 바꿔도 같은 저장값을 쓴다.
- 툴바 생성·표시·값 검사(12~24 정수)는 `chat-font.js`가 공용 API(`globalThis.chatDungsilFont`)로 제공하고, `content.js`·`chat-popup.js`와 모아보기 창(`watch.js`, 값 검사만)이 이를 쓴다. 툴바 스타일은 툴바를 넣는 문서마다 `<style id="chat-dungsil-font-toolbar-style">` 한 벌로 주입한다(PiP 문서에는 확장 CSS가 들어가지 않기 때문). 그래서 치지직·유튜브 최상위 페이지에는 `chat-font.js`가 `content.js`보다 먼저 들어가며, 유튜브 시청 페이지에서는 API만 제공하고 글자 크기 자동 적용은 하지 않는다.
- 스타일은 대상 문서에 `<style>`을 넣어 적용하므로 새 메시지와 DOM 교체에도 유지된다. 치지직 독립 채팅 iframe·팝업 창, 유튜브 `live_chat`/`live_chat_replay` 프레임에는 글자 크기 적용 스크립트가 들어가 저장소 변경을 받아 다시 적용한다.
- 모아보기 창도 치지직 글자 크기를 따른다.
- 치지직 자체 채팅 크기(%) 버튼은 확장 PiP iframe(`name=chat-dungsil-pip`)과 치지직 채팅 팝업 창에서 숨긴다.

### 결정과 이유

- 치지직 자체 배율 버튼은 닉네임·본문을 비율로 키우지만, 확장의 px 고정과 함께 쓰면 본문이 따라 커지지 않아 결과가 어긋난다. 조절 수단을 확장 도구 하나로 통일하려고 두 도구가 겹치는 PiP와 채팅 팝업 창에서 치지직 버튼을 숨긴다.
- 치지직 배율은 새로고침 시 100%로 돌아가 저장되지 않으므로, 숨겨도 이전 배율이 남아 확장 값과 섞이는 일은 없다.
- 처음에는 PiP에서만 툴바를 제공하려 했으나 사용자 요청으로 모든 채팅 표시 방식으로 넓혔다.

### 알려진 한계

- 일반 채팅 메시지만 대상이다. 유료·특수 채팅, 시스템 메시지는 사이트 원래 크기를 따른다.
- 셀렉터가 사이트 클래스 접두어에 의존하므로 사이트 개편 시 적용되지 않을 수 있다.

## 4. 치지직 상단 표시

### 현재 동작

- 채팅 상단 배너와 후원 순위를 각각 숨길 수 있다. 기본값은 모두 표시이며 설정을 저장한다. 숨긴 영역의 공간은 채팅이 쓴다.
- 방송 페이지 채팅, 독립 채팅 iframe(PiP), 치지직 채팅 팝업 창의 같은 영역에 적용한다. 채팅 메시지·고정 공지·입력창·기존 메뉴는 유지한다.
- 유튜브에서는 이 옵션을 표시하지 않는다.

### 결정과 이유

- 해시가 포함된 전체 클래스 이름 대신, 채팅 루트(`#aside-chatting` 또는 `role="log"`를 직계로 가진 `aside`)의 직계 배너(`_banner_` 접두어)와 순위 버튼(`_ranking_button_`)의 부모 구조로 대상을 좁힌다. 실제 방송 DOM에서 확인한 구조이며, 다른 영역을 잘못 숨기지 않기 위해서다.

### 알려진 한계

- 사이트 구조가 바뀌면 숨김이 적용되지 않을 수 있다.

## 5. 특정 사용자 모아보기

### 현재 동작

- 치지직 전용이다. 정확히 일치하는 닉네임 여러 명을 대상으로 등록하고, 수집을 시작한 뒤 화면에 새로 도착한 대상자의 일반 채팅을 모은다. 시작 시점에 화면에 있던 메시지는 기준선으로 제외한다.
- 메시지는 원본 방송 페이지의 메모리에 최근 1,000건까지만 보관한다. 새로고침·방송 주소 변경 시 수집을 멈추고 목록을 비운다. 수집 중지는 목록을 남긴다.
- 별도 창(`watch.html`)에 수집 시각·닉네임·본문을 표시한다. 자동 스크롤 끄기와 목록 비우기를 제공하고, 같은 원본 탭에 대해서는 기존 창을 재사용한다. 원본 탭이 닫히면 안내를 표시한다.
- 모아보기 PiP: 창 안의 「항상 위(PiP)」 버튼으로 헤더·목록 DOM을 Document PiP 창으로 옮긴다. 「창으로 되돌리기」나 PiP ✕로 원래 창에 돌려놓는다. 폴링·이벤트 처리는 원래 창의 스크립트가 계속 맡는다. 모아보기 창을 닫으면 PiP도 닫힌다.
- 채팅 PiP와 모아보기 PiP는 동시에 열 수 없다. 한쪽을 열면 다른 쪽이 닫히고, 닫힌 쪽은 원래 상태(채팅은 이전 도킹·플로팅 상태, 모아보기는 원래 창)로 복원한다.

### 결정과 이유

- 공개 DOM에서 사용자 ID·메시지 ID를 얻을 수 없어 닉네임을 기준으로 한다. 내부 React 상태나 인증 정보는 읽지 않는다.
- 화면의 위→아래 순서로 행을 정렬한 뒤 직전 목록과 겹치는 구간을 비교해 재렌더링으로 인한 중복을 제외한다. 치지직 DOM은 최신 메시지가 앞에 있지만 화면에서는 아래에 표시되므로 DOM 순서를 그대로 쓰지 않는다.
- 같은 문장의 실제 연속 전송은 요소 동일성까지 비교해 별도 건으로 유지한다.
- 겹치는 구간이 없는 전체 교체나 과거 스크롤은 신규 메시지로 단정하지 않고 기준선만 갱신한다. 중복 수집보다 누락을 택한 결정이다.
- 메시지는 `textContent`로 렌더링해 임의 HTML을 실행하지 않는다. 이모티콘은 `alt` 텍스트로 표시한다. 채팅 전송 기능은 두지 않는다.
- 메모리 사용을 제한하려고 1,000건 한도를 두고 화면에 한도를 표시한다.

### 알려진 한계

- 닉네임이 바뀌면 대상을 다시 등록해야 한다.
- 시작 전 과거 채팅, 화면에 도착하지 않았거나 건너뛴 메시지, 원본 삭제·차단 내역, 유료·특수 채팅은 완전하게 수집하지 않는다. 방송 채팅 기록 보관 도구가 아니다.

## 6. 채팅 팝업/팝아웃 전용 모드

### 현재 동작

- 대상은 최상위 창으로 열린 치지직 자체 채팅 팝업 창(`/live/<id>/chat`)과 유튜브 채팅 팝아웃 창(`/live_chat`, `/live_chat_replay`)이다.
- 이 창에서는 플로팅 스크립트(`content.js`)가 동작하지 않고, `chat-popup.js`가 창 상단 글자 크기 툴바와 확장 팝업의 메시지(`getStatus`, `setFontSize`, 치지직의 `setChatBannerHidden`·`setChatRankingHidden`)를 처리한다. 상태 응답에 `popupChat: true`를 담는다.
- 확장 팝업은 이 모드에서 플로팅·PiP·잠금·T 모드·투명도·단축키 안내를 숨긴다. 치지직 팝업 창은 글자 크기·상단 표시·모아보기를, 유튜브 팝아웃 창은 글자 크기만 표시한다.
- 툴바 위치는 치지직은 `role="log"`를 직계로 가진 `aside` 안 맨 앞, 유튜브는 `yt-live-chat-renderer #chat-messages` 안 맨 앞이다.

### 결정과 이유

- 이 창은 그 자체가 분리된 채팅이라 플로팅·PiP가 의미 없다. 치지직 팝업 창에서는 `content.js`가 종료되어 확장 팝업이 "새로고침 필요" 안내를 잘못 보였고, 유튜브 팝아웃 창에서는 `content.js`가 `[id*="chat"]` 후보로 채팅 영역을 도킹된 채팅창으로 오인해 플로팅 제어가 활성화되었다. 그래서 두 창 모두 `content.js`를 종료하고 전용 스크립트가 응답한다.
- 저장 객체를 방송 탭과 공유하므로, 이 창에서는 바꾼 항목만 읽어 합쳐 저장한다.

### 알려진 한계

- 치지직 채팅 팝업 창은 사이트의 창이므로 창 위치·크기와 항상 위 표시는 제어하지 않는다.

## 7. 저장소 구조와 동기화

### 현재 동작

모두 `chrome.storage.local`에 저장한다.

| 키 | 내용 |
| --- | --- |
| `chatDungsil:chzzk` | 치지직 설정 객체 |
| `chatDungsil:youtube` | 유튜브 설정 객체 |
| `chatDungsil:watchTargets:chzzk` | 모아보기 대상 닉네임 배열 |

사이트 설정 객체의 필드:

- `normal`, `theater`, `fs`: 모드별 `{ left, top, width, height }`
- `opacity`: 0~1
- `fontSize`: 12~24 정수 또는 `null`(사이트 기본값)
- `hideChatBanner`, `hideChatRanking`: 치지직 상단 표시
- `autoTheater`, `locked`

플로팅 중인지, 숨김 여부, PiP 열림 상태, 모아보기 메시지는 저장하지 않는다.

DOM id·class·창 이름 등 페이지에 넣는 식별자는 `chat-dungsil-*` 접두사를 쓴다.

### 결정과 이유

- 방송 탭의 `content.js`는 저장 시 설정 객체 전체를 쓰므로, 저장소 변경을 받아 바뀐 필드(위치·크기, 투명도, 잠금, T 자동 분리, 글자 크기, 상단 표시)를 모두 자기 상태에 반영한다. 다른 탭·채팅 팝업 창에서 바꾼 값을 이후 저장 때 이전 값으로 되돌리지 않기 위해서다. 플로팅 중이면 위치·투명도를 바로 다시 적용하고, 드래그·크기 조절 중에 받은 위치·크기는 반영하지 않고, 조작을 마치며 이 탭이 저장한 값이 우선한다. 다른 탭에서 잠금이 켜지면 진행 중인 조작을 취소한다.
- 첫 릴리스 전에 이름을 바꾸며 저장소 키도 새 이름으로 바꿨고, 이전 개발 버전 설정은 옮기지 않는다.

### 알려진 한계

- 같은 사이트의 여러 방송 탭은 위치·크기를 공유하므로, 한 탭에서 옮기면 플로팅 중인 다른 탭의 채팅도 같은 위치로 옮겨진다.
- 모아보기 대상 닉네임은 다른 탭의 변경을 실시간으로 받지 않는다. 여러 탭에서 동시에 수정하면 마지막에 저장한 목록이 남는다.

## 8. 검증 원칙

- 실제 확장을 Chromium에 로드하고 확장 메시지·저장소 경계를 그대로 쓰는 headless 회귀 검사를 둔다. 사용자 화면·포커스와 개인 Chrome 프로필은 건드리지 않는다.
- 합성 페이지로 사이트 DOM 조건을 재현하고, 실사이트는 로그인·채팅 전송 없이 새 메시지 표시만 확인한다. 유튜브는 headless 기본 User-Agent를 차단하므로 실사이트 확인 때 User-Agent를 바꾼다(세부는 [tests/README.md](../tests/README.md)).
- OS 창 동작(항상 위, 다른 앱 전체화면)이나 로그인이 필요한 동작처럼 확인하지 못한 범위는 결과 보고에서 구분한다.
